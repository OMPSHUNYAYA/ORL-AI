# ORL-AI Dependency Elimination

## Resolution-Authority Principle

Dependency elimination in ORL-AI concerns what is permitted to select the bounded admission result. It does not mean that models, clocks, networks, storage, review processes, or workflow systems physically disappear.

`operational mechanism != sole bounded resolution authority`

## Dependencies Removed from Sole Authority

| Dependency | Why it is insufficient by itself | ORL-AI structural replacement |
|---|---|---|
| Proposal arrival order | The first or last response may be incomplete, duplicated, delayed, or arbitrary | Canonical admitted observation set |
| Wall-clock timestamp | A later timestamp does not establish a better candidate | Frozen ruleset, profile, and sealed evidence boundary |
| Model response sequence | Sequential position does not establish correctness | Candidate-bound support, opposition, and abstention structure |
| One model output | A proposal is not authority | Required source classes and distinct source participation |
| Duplicate relay volume | Repetition from one source can imitate broader support | Distinct source-identifier counting |
| Declared confidence alone | A number may be uncalibrated or incomparable | Exact admission predicate without confidence authority |
| Caller-selected winner | The submitter must not directly grant authority | `authority_mode = NONE` and caller-derived authority refusal |
| Hidden tie-breaking | Silent ranking can force a result under disagreement | Explicit `ABSTAIN` states |
| Missing evidence completion | A partial set can appear conclusive | Exact expected observation and evidence boundary |
| Policy afterthought | A structurally eligible candidate may still be prohibited | Prohibition precedence and `DENIED` |

## Dependencies That May Remain Operational

ORL-AI integrations may still require:

- model inference;
- evidence collection and storage;
- source registration and authentication;
- network transport;
- workflow orchestration;
- clocks for freshness or expiry;
- human review;
- authorization;
- execution;
- logging, monitoring, and incident response.

The claim is narrower:

`same admitted canonical structure + same frozen profile + same ruleset -> same bounded admission state`

## Order-Independence Boundary

Set-like arrays are normalized before resolution. Equivalent orderings preserve the normalized commitment and decision resolution identity.

The exact submission commitment remains distinct, so provenance differences are not erased.

`order-independent decision != order-blind provenance`

## Duplicate-Multiplicity Boundary

Support thresholds count distinct source identifiers. Ten support observations from one source remain one participating source.

This prevents relay multiplicity from becoming support authority within the model. It does not provide network replay protection or source authentication.

## Time Boundary

The current profile contains no wall-clock field. Time cannot break ties or complete missing evidence.

A time-sensitive profile would need explicit time evidence, deterministic freshness rules, a new profile identifier, and new verification artifacts.

## AI Boundary

The model output is treated as a typed candidate proposal. ORL-AI does not determine whether the model reasoned correctly, whether its explanation is faithful, or whether the proposal is factually grounded.

`model proposal + declared corroboration != proven truth`

## Conservative Outcome Boundary

When the declared structure cannot support one candidate, ORL-AI does not force a winner. It returns `INCOMPLETE`, `ABSTAIN`, `DENIED`, or `REFUSED` according to the frozen precedence.
