⭐ ORL-AI — VERIFICATION GUIDE

Deterministic Bounded Structural Decision Resolution

This guide defines the recommended procedure for verifying the current ORL-AI Python reference implementation and its committed output artifact.

ORL-AI normalizes input signal strings, checks an embedded conflict-pair table, applies an embedded decision-rule table, and returns one of three bounded resolver states:

- RESOLVED
- INCOMPLETE
- ABSTAIN

Current governing relation:

same normalized supported signal set + same embedded conflict pairs + same embedded decision rules -> same bounded decision state and current result hash

ORL-AI is developed within the Shunyaya Framework.

===============================================================================
1. SCOPE
===============================================================================

This guide applies to:

demo/orl_ai_demo_base_v4_1.py
outputs/orl_ai_result_v4_1.json
VERIFY/VERIFY.txt
VERIFY/FREEZE_DEMO_SHA256.txt

The current verification procedure may establish:

- successful Python execution;
- expected committed scenario results;
- deterministic normalization of the committed signal strings;
- explicit conflict and decision-rule evaluation;
- repeatable current result hashes;
- equality between committed reference and replay groupings;
- all six permutations of the three committed reference node groups;
- regeneration of the reference JSON output;
- byte identity of frozen artifacts when SHA-256 values match.

It does not establish:

- general artificial intelligence;
- unrestricted decision correctness;
- universal order independence;
- universal time independence;
- universal synchronization independence;
- autonomous networking or evidence delivery;
- distributed consensus;
- independent proof reconstruction;
- cross-language conformance;
- security;
- production readiness;
- medical, legal, financial, cybersecurity, or operational validity.

===============================================================================
2. REQUIREMENTS
===============================================================================

Recommended environment:

Python 3.9 or later

The current demo uses only Python standard-library modules.

No third-party runtime package is required.

The resolver does not use GPS, NTP, a runtime database, a live server, wall-clock time, or runtime internet access as decision inputs.

3. RUN THE REFERENCE DEMO
===============================================================================

Open Command Prompt, PowerShell, Terminal, or another shell in the repository root.

Run:

python demo/orl_ai_demo_base_v4_1.py

On systems where python does not select Python 3, use:

python3 demo/orl_ai_demo_base_v4_1.py

The process should complete without an unhandled exception.

A zero exit code alone is not sufficient because the current script prints checks but does not enforce every failed condition through a non-zero exit code.

Review the displayed results.

===============================================================================
17. PASS CONDITIONS
===============================================================================

Verification passes when:

- the Python process completes without an unhandled exception;
- each local reference node is INCOMPLETE;
- the reference merge is RESOLVED -> Action_Isolate;
- the regrouped replay produces the same state, decision, and current hash;
- the explicit conflict returns ABSTAIN;
- the ambiguity case returns ABSTAIN;
- the nominal five-node and replay cases resolve to Action_Approve;
- the approval path resolves to Action_Approve;
- the escalation path resolves to Action_Escalate;
- the same-decision overlap resolves to Action_Approve;
- the conflict regrouping remains REJECTED_CONFLICT;
- exactly six reference-group permutations are checked;
- permutation independence is True;
- all six displayed Boolean comparison checks are True;
- the two overlap values match the expected state and action;
- all eight JSON final_checks values are true;
- repeated unchanged JSON generation is byte-identical;
- frozen artifact hashes match.

===============================================================================
18. FAILURE CONDITIONS
===============================================================================

Treat verification as failed when:

- the script raises an unhandled exception;
- the expected output file is not created;
- the reference merge does not resolve to Action_Isolate;
- the reference and replay results differ;
- the conflict case does not return ABSTAIN;
- the ambiguity case does not return ABSTAIN;
- the overlap case does not resolve to Action_Approve;
- the permutation count is not six;
- permutation independence is not True;
- any expected Boolean comparison is False;
- either overlap value differs;
- any generated JSON final_checks value is false;
- repeated unchanged JSON generation differs;
- frozen hashes differ unexpectedly.

A frozen-hash mismatch may indicate an intentional local modification.

Review the repository diff before treating the mismatch as corruption.

===============================================================================
19. CURRENT RESULT-HASH BOUNDARY
===============================================================================

The function named certificate(...) hashes a delimiter-based text payload containing:

- normalized structure;
- state;
- decision;
- matched decisions.

Current relation:

same current payload bytes -> same SHA-256 hash

A matching current result hash does not by itself prove:

- correct rule design;
- factual decision truth;
- schema validity;
- signal authenticity;
- independent reconstruction;
- security;
- production safety.
